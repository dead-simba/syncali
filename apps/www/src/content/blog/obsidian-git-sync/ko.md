무료 Obsidian 동기화를 검색하다 보면 결국 누군가는 이렇게 말합니다. 그냥 Git 쓰면 된다고요.

포럼과 Reddit에서 자주 나오는 조언입니다. Obsidian 노트는 Markdown 파일이고 Git은 무료이며 GitHub 같은 곳에 vault 사본을 둘 수 있습니다. 말만 들으면 완벽해 보입니다.

하지만 Git을 써본 적이 없다면 금방 헷갈릴 수도 있습니다.

Git은 동기화 버튼이 아닙니다. 폴더의 상태를 시간에 따라 스냅샷으로 저장하고 그 스냅샷을 컴퓨터 사이로 옮기는 시스템입니다. 개발자들은 코드를 위해 매일 씁니다. 노트 사용자도 쓸 수 있지만 iCloud나 Dropbox나 Obsidian Sync와는 습관이 다릅니다.

그래서 진짜 질문은 단순히 이게 아닙니다.

> Git으로 Obsidian을 동기화할 수 있나?

더 중요한 질문은 이쪽입니다.

> 노트를 맞춰 두려고 개발자식 저장-업로드 흐름을 새로 배울 생각이 있나?

이 글은 Obsidian Git 동기화를 쉬운 말로 설명합니다. 사람들이 왜 좋아하는지와 일상적인 Obsidian 사용자에게 어디서 막히는지 그리고 Synch 같은 종단 간 암호화 대안이 언제 더 단순한지도 정리합니다.

## Obsidian 관점에서 본 Git

Git을 자동 클라우드 동기화가 아니라 신중한 노트 히스토리 시스템으로 생각해 보세요.

일상어로 바꾸면 이렇게입니다.

- **repository(저장소)** 는 vault 폴더에 숨겨진 변경 이력이 붙은 것입니다.
- **commit** 은 스냅샷입니다. "지금 노트 상태를 저장한다"는 뜻입니다.
- **push** 는 그 스냅샷을 온라인 사본(보통 GitHub)으로 올리는 일입니다.
- **pull** 은 온라인 사본에서 더 새 스냅샷을 다른 기기로 받아오는 일입니다.
- **merge conflict** 는 두 기기가 서로를 보기 전에 같은 노트를 바꿔서 버전이 충돌한 상태입니다.

Git은 글을 쓰는 동안 모든 기기를 조용히 최신으로 맞춰 주지 않습니다. 스냅샷을 저장하고 옮길 때 노트가 이동합니다.

이게 핵심 트레이드오프입니다.

일반 동기화 서비스에서는 노트를 수정하면 다른 기기가 따라오길 기대합니다.

Git에서는 노트를 수정하고 스냅샷을 저장하고 업로드한 뒤 다른 기기에서 이어서 쓰기 전에 반드시 받아와야 합니다.

## Obsidian Git 동기화는 보통 이렇게 동작합니다

대부분의 "Obsidian Git 동기화" 설정은 이런 흐름입니다.

1. vault 폴더를 Git 저장소로 만듭니다.
2. 노트 변경을 스냅샷으로 저장합니다.
3. 그 스냅샷을 비공개 온라인 저장소에 올립니다.
4. 다른 컴퓨터에서 같은 저장소를 받아 Obsidian으로 엽니다.

많은 사람이 [Obsidian Git](https://github.com/Vinzent03/obsidian-git) 커뮤니티 플러그인을 씁니다. 터미널에 오래 머물지 않고 Obsidian 안에서 더 많은 작업을 할 수 있기 때문입니다.

기본 경로는 이렇게 보입니다.

```txt
기기 A의 Obsidian vault
        |
스냅샷 저장 + 업로드
        |
온라인 Git 사본
        |
최신 스냅샷 다운로드
        |
기기 B의 Obsidian vault
```

온라인 Git 사본이 기기 사이의 중간 지점입니다. 조심하면 잘 동작할 수 있습니다.

그래도 스냅샷을 저장하고 옮기는 일은 본인이나 플러그인이 기억해야 합니다. 노트를 수정하는 것과 노트를 동기화하는 것은 같은 일이 아닙니다.

## 그래도 사람들이 Git을 추천하는 이유

사람들이 Git을 추천하는 이유는 무료에 가깝고 투명하며 히스토리에 강하기 때문입니다.

얻을 수 있는 것은:

- vault의 온라인 사본을 무료 또는 저비용으로 유지하는 방법
- 노트 변경의 자세한 이력
- Markdown 노트의 이전 버전과 새 버전을 비교하는 방법
- vault를 아무 클라우드 폴더에 그냥 넣는 것보다 더 많은 통제권
- Obsidian Sync 구독 없이도 가능한 구성

무료 동기화와 예전 버전 복구가 중요하다면 매력적으로 들립니다.

반대로 원하는 게 "폰에서 Obsidian을 열어 짧게 적고 노트북에 곧 반영되길 믿는 것"이라면 매력이 줄어듭니다.

## Git을 시도하기 전에 필요한 것

Git이 처음이라면 동기화가 부드럽게 느껴지기까지 학습 곡선이 있습니다.

보통 이런 것들을 이해해야 합니다.

- 비공개 온라인 저장소를 만드는 방법
- Obsidian을 그 저장소에 연결하는 방법
- 노트 스냅샷을 저장하는 방법
- 변경을 올리고 받는 방법
- 같은 노트의 두 버전이 다를 때 할 일
- 히스토리에 넣으면 안 되는 파일

시작 전에 별도 백업도 필요합니다. vault 전체를 안전한 곳에 먼저 복사하세요. 동기화 도구는 실수도 빠르게 복사합니다. Git도 예외가 아닙니다.

생각보다 중요한 설정 포인트도 있습니다.

- 공개 노트를 의도한 게 아니라면 온라인 저장소는 **비공개**로 두세요.
- `.obsidian` 안의 Obsidian 설정을 포함할지 초기에 정하세요.
- 비밀번호나 토큰이나 비밀 플러그인 설정을 저장소에 넣지 마세요.
- 같은 vault를 iCloud나 Dropbox나 Google Drive나 OneDrive나 Syncthing과 동시에 동기화하지 마세요.

이 단계만으로도 이미 부담스럽다면 Git은 원하는 동기화 방식이 아닐 가능성이 큽니다.

## Git이 잘 맞는 경우

Git은 Obsidian 루틴이 차분하고 주로 데스크톱 중심일 때 잘 맞습니다.

이런 경우에 더 적합합니다.

- vault가 사진과 PDF보다 텍스트 노트 위주일 때
- 한 번에 주로 한 컴퓨터에서 수정할 때
- 다른 기기에서 쓰기 전에 최신 노트를 받을 의이 있을 때
- 보이지 않는 백그라운드 동기화보다 자세한 히스토리를 더 중요하게 여길 때
- 새 개념을 조금 배우는 걸 꺼리지 않을 때
- 폰이 메인 작성 장소가 아니라 보조일 때

현실적인 "좋은 하루"는 이런 모습입니다.

1. 노트북에서 Obsidian을 엽니다.
2. 최신 노트가 있는지 확인합니다.
3. 잠시 글을 씁니다.
4. 스냅샷을 저장합니다.
5. 업로드합니다.
6. 나중에 다른 컴퓨터에서는 수정하기 전에 먼저 받습니다.

이 리듬이 자연스럽다면 Git은 안정적일 수 있습니다.

동기화 상태를 생각하지 않고 폰과 노트북을 자주 오간다면 Git은 계속 부딪힐 가능성이 큽니다.

## Obsidian Git 동기화가 어려워지는 지점

### 1. 일반 동기화처럼 느껴지지 않습니다

Obsidian Sync나 iCloud나 전용 동기화 앱에서는 생각이 단순합니다. 여기서 고치면 저기서 보입니다.

Git에서는 생각이 다릅니다. 여기서 고치고 스냅샷을 저장하고 올리고 저기서 받습니다.

플러그인이 일부를 자동화할 수 있습니다. 하지만 기본 아이디어는 없애지 못합니다. 스냅샷이 올라가지 않았다면 다른 기기에는 그 노트가 없습니다.

### 2. 충돌이 글쓰기를 방해합니다

폰과 노트북이 동기화 전에 같은 노트를 고치면 Git은 어느 쪽이 맞는지 조용히 추측하지 않습니다. 노트 안에 충돌 표시가 생기고 직접 정리해야 할 수 있습니다.

한쪽을 조용히 지우는 것보다는 안전합니다. 그래도 짧게 적으려던 순간에는 여전히 거슬립니다.

도구를 막론하고 Obsidian 동기화 충돌이 어떻게 생기는지 더 보고 싶다면 [동기화 중 노트가 복제되거나 사라지는 이유](/ko/blog/obsidian-sync-conflicts)를 읽어 보세요.

### 3. 폰이 약점입니다

데스크톱 Git 설정도 이미 프로젝트입니다. 모바일 Git은 더 어렵습니다.

폰에서는 추가 앱이나 추가 로그인이나 불안한 플러그인 흐름이 필요할 수 있습니다. 빠른 메모가 느려지고 충돌 수리가 어려워지며 큰 vault는 더 무거워집니다.

동기화의 주된 이유가 "낮에 폰으로 적는다"라면 Git은 보통 첫 선택이 아닙니다.

### 4. 이미지와 PDF가 무거워집니다

Git은 히스토리를 기억합니다. 텍스트에는 좋습니다. 큰 파일에는 어색합니다.

vault에 이미지나 PDF나 녹음이 많으면 온라인 사본이 빠르게 커질 수 있습니다. 나중에 큰 파일을 지워도 히스토리가 바로 작아지지 않을 수 있습니다. 미디어가 많은 vault는 보통 혼합 파일을 다루는 동기화 시스템이 더 편합니다.

### 5. 비공개와 암호화는 다릅니다

비공개 GitHub 저장소는 공개 인터넷에서 숨겨집니다. 그건 좋습니다.

하지만 종단 간 암호화와는 다릅니다.

노트가 일반 Markdown으로 올라가면 Git 호스트는 읽을 수 있는 노트 내용을 저장할 수 있습니다. 일기나 건강 기록이나 업무 노트나 민감한 내용이라면 이 차이가 중요합니다.

Synch는 업로드 전에 기기에서 vault 데이터를 암호화하므로 동기화 서버는 읽을 수 있는 노트가 아니라 암호화된 데이터를 저장합니다. 쉬운 기술 설명이 필요하면 [Synch의 종단 간 암호화 방식](/ko/blog/encryption-and-decryption)을 읽어 보세요.

### 6. 한 vault에 동기화 시스템을 두 개 쓰는 건 흔한 재난입니다

Git으로 관리하는 vault를 iCloud나 Dropbox나 Google Drive나 OneDrive나 Syncthing 안에 두고 Git 스냅샷 자동화까지 동시에 돌리지 마세요. 같은 폴더를 두 시스템이 놓고 싸우면 복제본이나 사라진 수정이나 혼란스러운 히스토리가 생기기 쉽습니다.

매일 쓰는 vault에는 활성 동기화 방법을 하나만 고르세요.

## Git vs Synch

Git과 Synch는 다른 문제를 풀려고 합니다.

Git은 히스토리와 전송 도구입니다. Synch는 Obsidian을 위해 만든 오픈소스 종단 간 암호화 동기화 서비스입니다.

| 질문 | Git | Synch |
| --- | --- | --- |
| 무엇을 위한가? | 노트 히스토리를 저장하고 기기 사이로 스냅샷을 옮김 | Obsidian vault 동기화 |
| 별도 단계를 배워야 하나? | 예: 스냅샷·업로드·다운로드·충돌 정리 | 훨씬 적음 |
| 일반 동기화처럼 느껴지나? | 자동화해도 조심해야 함 | 그것이 목표 |
| 기본적으로 종단 간 암호화되나? | 일반 Git 호스트에서는 아님 | 예. 업로드 전 기기에서 암호화 |
| 폰에 친화적인가? | 종종 어려움 | 다중 기기 Obsidian 사용을 염두에 둠 |
| 누구에게 맞나? | Git식 히스토리를 원하고 흐름을 관리할 수 있는 사람 | Git을 배우지 않고 프라이빗 Obsidian 동기화를 원하는 사람 |

히스토리와 통제가 핵심이고 시스템을 직접 운영할 의사가 있다면 Git이 끌립니다.

노트 작성을 저장소 관리로 바꾸지 않고 기기 사이로 노트를 옮기고 싶다면 Synch가 끌립니다.

## 그래도 Git이 가치 있을 때

Git을 선택하세요. 만약:

- 기초를 천천히 배울 호기심이 있다면
- 주로 데스크톱에서 쓴다면
- vault가 텍스트 중심이라면
- 자세한 변경 이력이 필요하다면
- 일부러 멈춰서 동기화하는 게 괜찮다면
- 비공개 저장소 수준이면 프라이버시가 충분하다면

그래도 작게 시작하세요. 먼저 테스트 vault를 쓰세요. 수년치 노트의 유일한 사본으로 시작하지 마세요.

## Synch가 더 맞는 경우

진짜 원하는 게 미니 Git 프로젝트가 아니라 Obsidian 동기화라면 Synch를 선택하세요.

Synch가 더 맞는 경우는:

- 노트를 맞추려고 commit이나 pull이나 merge를 배우고 싶지 않을 때
- 데스크톱과 모바일 모두에서 쓸 때
- 기본적으로 종단 간 암호화를 원할 때
- 일반 클라우드 드라이브 없이 호스팅 동기화를 원할 때
- Obsidian Sync의 무료 또는 저비용 대안을 원할 때
- Git + 플러그인 + 원격 호스트보다 움직이는 부품이 적길 원할 때

현재 Synch Free 플랜은 동기화 vault 1개와 저장 공간 50 MB와 최대 파일 크기 3 MB와 버전 히스토리 1일을 포함합니다. Starter 플랜은 동기화 vault 1개와 저장 공간 1 GB와 최대 파일 크기 5 MB와 버전 히스토리 1개월을 포함합니다.

작은 개인 vault나 학생이나 취미 노트 그리고 개발 도구를 먼저 배우지 않고 프라이빗 암호화 동기화를 원하는 사람에게 Synch는 실용적입니다.

아직 넓게 비교 중이라면 [2026년 최고의 Obsidian Sync 대안](/ko/blog/obsidian-sync-alternatives)과 [무료 Obsidian 동기화 옵션](/ko/blog/free-obsidian-sync)을 보세요.

## 그래도 Git을 쓴다면

설정은 지루하고 신중하게 유지하세요.

1. 먼저 vault 전체를 안전한 곳에 복사합니다.
2. 비공개 온라인 저장소를 씁니다.
3. 가능하면 작은 테스트 vault로 시작합니다.
4. 한 루프를 잘 익힙니다: 최신 받기 → 쓰기 → 스냅샷 저장 → 업로드.
5. 두 번째 기기에서는 수정 전에 항상 받습니다.
6. 같은 노트를 두 기기에서 동시에 고치지 않습니다.
7. 가능하면 큰 첨부 파일은 빼 둡니다.
8. 같은 폴더에서 Git과 다른 동기화 도구를 함께 쓰지 않습니다.

첫 주가 도움이 아니라 스트레스로 느껴진다면 그것도 유용한 정보입니다. Git은 강력할 수 있지만 당신의 노트 생활에 맞는 동기화 도구는 아닐 수 있습니다.

## FAQ

### 개발자가 아닌데 Git으로 Obsidian을 동기화할 수 있나요?

가능합니다. 다만 학습 곡선을 예상하세요. Git은 소프트웨어 히스토리를 위해 만들어졌고 가벼운 노트 동기화를 위해 만들어지지 않았습니다. 많은 Obsidian 사용자가 필요한 만큼 배울 수 있습니다. 많은 다른 사용자는 자기가 원한 게 동기화였지 새로 관리할 시스템이 아니었다고 결론 내립니다.

### Obsidian Git 플러그인만으로 충분한가요?

데스크톱에서는 Obsidian 안에 버튼과 자동화를 줘서 도움이 됩니다. 하지만 스냅샷과 업로드와 다운로드와 충돌과 프라이버시 설정을 이해해야 한다는 점은 사라지지 않습니다.

### Git은 좋은 무료 Obsidian Sync 대안인가요?

무료이거나 저렴할 수 있습니다. 숨은 비용은 시간과 주의입니다. 무료가 가장 중요하고 만지작거리는 걸 즐긴다면 Git은 시도할 만합니다. 덜 생각해도 노트가 맞춰지길 원한다면 전용 동기화 옵션을 보세요.

### 비공개 GitHub 저장소는 종단 간 암호화인가요?

아닙니다. 비공개는 다른 사람이 쉽게 훑어볼 수 없다는 뜻입니다. 호스트가 읽을 수 없는 암호문만 저장한다는 뜻이 아닙니다. 종단 간 암호화된 호스팅 동기화가 필요하다면 그걸 위해 만든 도구를 쓰세요.

### Git과 Synch 중 무엇을 써야 하나요?

저장소 형태의 노트 히스토리를 원하고 그 흐름을 배울 의사가 있다면 Git을 쓰세요. Git을 직접 관리하지 않고 프라이빗한 종단 간 암호화 Obsidian 동기화를 원한다면 Synch를 쓰세요.

### Git과 Synch를 같이 쓸 수 있나요?

같은 활성 vault에서는 안 됩니다. 따로 백업 사본을 둘 수는 있지만 작업 중인 폴더를 활성 동기화 시스템 두 개가 동시에 관리하게 하지 마세요.

## 결론

Git으로 Obsidian vault를 동기화할 수 있습니다. 히스토리를 좋아하는 신중한 데스크톱 작성자에게는 잘 맞을 수 있습니다.

하지만 많은 일상적인 Obsidian 사용자에게는 첫 답이 아닙니다. 스냅샷과 업로드와 다운로드와 충돌 정리를 생각해야 합니다. 원하는 게 그저 모든 기기의 노트라면 절차가 많습니다.

Git을 배우는 게 즐겁고 워크플로가 주로 데스크톱 텍스트 노트라면 Obsidian Git 동기화는 강한 무료 옵션이 될 수 있습니다.

관리할 일이 더 적고 종단 간 암호화된 프라이빗 Obsidian 동기화를 원한다면 Synch가 그 일을 위해 만들어졌습니다.
