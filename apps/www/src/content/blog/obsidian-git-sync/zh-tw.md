搜免費 Obsidian 同步時，總會有人說：用 Git 就行。

論壇和 Reddit 裡這種建議很常見。Obsidian 筆記是 Markdown，Git 免費，GitHub 還能存一份 vault 副本——聽起來無懈可擊。

可如果你本來不會 Git，這份「簡單」很快就會變得難懂。

Git 不是同步按鈕。它會按時間把資料夾狀態做成快照，再把快照傳到其他電腦。開發者每天用它管程式碼；記筆記的人也能用，但習慣和 iCloud、Dropbox、Obsidian Sync 完全不同。

所以真正該問的不是：

> Git 能同步 Obsidian 嗎？

而是：

> 你願不願意，只為了讓筆記對齊，去學一套偏開發者的「先儲存再上傳」流程？

下面用白話講清 Obsidian 的 Git 同步：人們為什麼喜歡它、日常使用者容易卡在哪裡，以及 Synch 這類端對端加密同步什麼時候更省事。

## 用 Obsidian 的話說，Git 是什麼

別把 Git 當成自動雲端同步，把它當成一套謹慎的筆記歷史系統。

換成日常說法：

- **repository（儲存庫）** 就是 vault 資料夾，再帶上隱藏的變更歷史。
- **commit** 是一次快照：把「目前筆記狀態」存下來。
- **push** 是把快照上傳到線上副本，常見目標是 GitHub。
- **pull** 是從線上副本把更新拉到另一台裝置。
- **merge conflict** 是兩台裝置還沒看到對方，就改了同一篇筆記，版本撞車了。

你寫作時，Git 不會默默把每台裝置都更新好。筆記只有在快照被儲存並傳過去時才會移動。

這就是最大的差別。

普通同步裡，你這邊改完，就期待那邊跟上。

在 Git 裡，你要改完、存快照、上傳，再到另一台裝置繼續寫之前，先下載。

## Obsidian Git 同步一般怎麼做

常見做法大致是：

1. 把 vault 資料夾變成 Git 儲存庫。
2. 把筆記改動存成快照。
3. 上傳到私人線上儲存庫。
4. 在另一台電腦下載同一儲存庫，用 Obsidian 開啟。

不想整天泡在終端機裡的人，多用 [Obsidian Git](https://github.com/Vinzent03/obsidian-git) 社群外掛，在 Obsidian 裡就能完成更多操作。

整體路徑如下：

```txt
裝置 A 上的 Obsidian vault
        |
儲存快照 + 上傳
        |
線上 Git 副本
        |
下載最新快照
        |
裝置 B 上的 Obsidian vault
```

中間的線上 Git 副本是裝置之間的中轉。小心用，可以跑得很穩。

但它仍然依賴你或外掛記得存快照並傳出去。改了筆記，不等於已經同步完。

## 為什麼還有人推薦 Git

因為它往往免費、透明，而且擅長歷史紀錄。

你能得到：

- 用免費或低成本方式保留 vault 的線上副本
- 筆記改動的詳細歷史
- 比較同一篇 Markdown 新舊版本
- 比把 vault 隨便丟進雲端資料夾更強的控制權
- 不必訂閱 Obsidian Sync 也能搭起來

如果你要的是免費同步，又在意復原舊版本，這很有吸引力。

如果你真正想要的是：手機開啟 Obsidian 隨手記一句，並相信筆記型電腦很快會看到——那吸引力就小多了。

## 動手前先搞清楚這些

Git 新手在同步感覺順暢之前，都會有學習成本。

通常需要搞懂：

- 怎麼建立私人線上儲存庫
- 怎麼把 Obsidian 連上那個儲存庫
- 怎麼儲存筆記快照
- 怎麼上傳、下載改動
- 同一篇筆記出現兩個版本時怎麼辦
- 哪些檔案不該寫進歷史

開始前務必單獨備份。先把整個 vault 複製到安全位置。同步工具會很快把錯誤也複製出去，Git 也不例外。

還有幾項聽起來不起眼、其實很要緊：

- 不打算公開筆記，就把線上儲存庫設為**私人**。
- 儘早決定要不要把 `.obsidian` 裡的設定一併納入。
- 不要把密碼、權杖或機密外掛設定放進儲存庫。
- 不要同時用 iCloud、Dropbox、Google Drive、OneDrive 或 Syncthing 同步同一個 vault。

如果這些步驟已經讓你覺得負擔太重，Git 多半不是你要的同步方式。

## 誰更適合用 Git

節奏穩、主要在電腦上寫 Obsidian 的人，更容易用好。

尤其適合這些情況：

- vault 以文字為主，不是大量照片和 PDF
- 同一時間主要在一台電腦上改
- 願意在另一台裝置寫作前先拉最新內容
- 比起看不見的背景同步，更看重詳細歷史
- 不介意學幾個新概念
- 手機是輔助，不是主力

順暢的一天通常是這樣：

1. 在筆記型電腦上開啟 Obsidian。
2. 確認已經是最新。
3. 寫一段時間。
4. 儲存快照。
5. 上傳。
6. 之後在另一台電腦上，改之前先下載。

如果這個節奏自然，Git 可以很可靠。

如果你經常在手機和筆記型電腦之間切換、卻不想管同步狀態，Git 會和你較勁。

## Obsidian Git 同步哪裡容易變難

### 1. 它不像普通同步

Obsidian Sync、iCloud 或專用同步應用，心智模型很簡單：這裡改，那裡見。

Git 不一樣：這裡改，存快照，上傳，再到那裡下載。

外掛可以自動化一部分，消不掉底層思路。快照沒上傳成功，另一台裝置就不會有那篇筆記。

### 2. 衝突會打斷寫作

手機和筆記型電腦在同步前都改了同一篇，Git 不會默默猜哪個對。你可能在筆記裡看到衝突標記，並要自己清理。

這比悄悄刪掉一個版本更安全。但你只想隨手記一句時，仍然很煩。

想更完整了解各類工具裡 Obsidian 同步衝突如何發生，可看 [為什麼同步時筆記會重複或消失](/zh-tw/blog/obsidian-sync-conflicts)。

### 3. 手機是薄弱環節

桌面端 Git 已經夠折騰。行動端更難。

手機上可能還要額外應用、額外登入，或脆弱的外掛流程。快速記錄變慢，衝突修復變難，大 vault 也更重。

如果你同步的主要原因是「白天用手機寫」，Git 通常不是首選。

### 4. 圖片和 PDF 會把儲存庫撐大

Git 會記住歷史。這對文字很好，對大檔案很彆扭。

圖片、PDF、錄音一多，線上副本很快膨脹。以後刪掉大檔案，歷史體積也不一定立刻縮小。媒體多的 vault，通常更適合為混合檔案設計的同步系統。

### 5. 私人不等於加密

私人 GitHub 儲存庫對公開網際網路隱藏，這很好。

但這不是端對端加密。

筆記以普通 Markdown 上傳時，Git 託管方可保存可讀內容。對日記、健康紀錄、工作筆記或任何敏感內容，差別很大。

Synch 會在上傳前於裝置上加密 vault 資料，同步伺服器存的是密文，而不是可讀筆記。想看通俗技術說明，可讀 [Synch 的端對端加密如何運作](/zh-tw/blog/encryption-and-decryption)。

### 6. 一個 vault 疊兩套同步，很容易出事

不要把 Git 管理的 vault 放進 iCloud、Dropbox、Google Drive、OneDrive 或 Syncthing，同時又讓 Git 自動做快照。兩套系統爭搶同一資料夾，很容易出現重複、丟編輯、歷史混亂。

每天寫作的 vault，只保留一種正在使用的同步方式。

## Git vs Synch

兩者解決的問題不同。

Git 是歷史與傳輸工具。Synch 是為 Obsidian 做的開源端對端加密同步服務。

| 問題 | Git | Synch |
| --- | --- | --- |
| 用來做什麼？ | 留下筆記歷史，並在裝置間移動快照 | 同步 Obsidian vault |
| 要不要學額外步驟？ | 要：快照、上傳、下載、衝突清理 | 少得多 |
| 感覺像普通同步嗎？ | 自動化做得好時才接近 | 這正是目標 |
| 預設端對端加密嗎？ | 普通 Git 託管上不是 | 是，上傳前在裝置上加密 |
| 手機友善嗎？ | 常常困難 | 面向多裝置 Obsidian 使用 |
| 適合誰？ | 想要 Git 式歷史、也能自己管流程的人 | 不想學 Git、又想要私密 Obsidian 同步的人 |

歷史和控制才是重點，並且你願意自己操作系統時，Git 有吸引力。

希望筆記在裝置間流動，又不想把記筆記變成儲存庫維護時，Synch 更有吸引力。

## 什麼時候 Git 仍然值得

下面這些情況可以考慮 Git：

- 願意慢慢學基礎
- 主要在桌面端寫作
- vault 以文字為主
- 需要詳細變更歷史
- 願意主動停下來做同步
- 私人儲存庫的隱私程度對你足夠

即便如此，也從小處開始。先用測試 vault，不要拿唯一一份多年筆記開刀。

## 什麼時候 Synch 更合適

如果你真正想要的是 Obsidian 同步，而不是一個迷你 Git 專案，就選 Synch。

尤其適合這些情況：

- 不想為了同步去學 commit、pull、merge
- 電腦和手機都要寫
- 預設就要端對端加密
- 想要託管同步，又不想用通用雲端硬碟
- 想要 Obsidian Sync 的免費或低成本替代
- 想比 Git + 外掛 + 遠端託管更簡單

目前 Synch Free 方案包含 1 個同步 vault、50 MB 儲存空間、3 MB 最大檔案大小，以及 1 天版本歷史。Starter 方案包含 1 個同步 vault、1 GB 儲存空間、5 MB 最大檔案大小，以及 1 個月版本歷史。

對小型個人 vault、學生和嗜好筆記，以及不想先學開發者工具就想要私密加密同步的人來說，Synch 很實用。

## 如果你還是想用 Git

把設定保持得簡單、謹慎。

1. 先把整個 vault 複製到安全位置。
2. 使用私人線上儲存庫。
3. 可以的話先從小測試 vault 開始。
4. 把一個循環練熟：下載最新 → 寫作 → 儲存快照 → 上傳。
5. 在第二台裝置上，改之前總是先下載。
6. 避免同時在兩台裝置改同一篇筆記。
7. 盡量不要納入大附件。
8. 不要在同一資料夾上把 Git 和另一套同步工具疊用。

如果第一週帶來的是壓力而不是幫助，這也是答案。Git 可能很強，但不一定適合你的筆記習慣。

## FAQ

### 我不是開發者，能用 Git 同步 Obsidian 嗎？

可以，但要預期學習成本。Git 是為軟體歷史設計的，不是為輕鬆的筆記同步設計的。很多人能學會夠用的部分；也有很多人最終發現，自己想要的是同步，不是又一套要維護的系統。

### 只裝 Obsidian Git 外掛夠嗎？

在桌面端，它能提供按鈕和自動化，很有幫助。但你仍需理解快照、上傳、下載、衝突和隱私設定。

### Git 是好的免費 Obsidian Sync 替代嗎？

可以免費或便宜。隱藏成本是時間和注意力。如果免費最重要，又喜歡折騰，值得一試。如果希望少想一點筆記就能對齊，看看專用同步方案。

### 私人 GitHub 儲存庫是端對端加密嗎？

不是。私人表示別人不能隨便瀏覽，並不表示託管方只保存自己讀不了的密文。需要端對端加密的託管同步，請用為此設計的工具。

### 我該用 Git 還是 Synch？

想要儲存庫式筆記歷史，並願意學習那套流程，用 Git。想要私密的端對端加密 Obsidian 同步，又不想自己管 Git，用 Synch。

### 可以同時用 Git 和 Synch 嗎？

不能用在同一個正在使用的 vault 上。你可以另存一份備份，但不要讓兩套正在執行的同步系統同時管理一個工作資料夾。

## 總結

Git 可以同步 Obsidian vault。喜歡歷史、寫作節奏謹慎的桌面使用者，用起來可以很好。

但對很多日常 Obsidian 使用者來說，它不是首選。它要求你持續想著快照、上傳、下載和衝突清理。如果你只想要每台裝置都有筆記，儀式感就太多了。

如果你喜歡學 Git，而且主要在桌面寫文字筆記，Obsidian Git 同步可以是很強的免費選項。

如果你想要端對端加密的私密 Obsidian 同步，並且少管一點細節，Synch 就是為此而建的。
